Factory Inventory Management System

Architecture overview — full-stack demo for inventory, orders, demand forecasting, and spending analytics.

Vue 3 SPA FastAPI In-memory JSON data No database No auth

Overview

A single-page Vue 3 application talks to a stateless Python FastAPI service over HTTP/JSON. The API has no database: at startup it loads six JSON files from server/data/ into module-level Python lists and dicts, then serves and filters them in memory. Every request re-filters the original datasets; nothing is persisted, so restarting the server resets all state.

Request Data Flow — Dashboard with Filters

The four global filters (Time Period, Warehouse, Category, Order Status) live in a singleton composable and apply to every data view. A typical round trip:

  1. User changes a dropdown in FilterBar.vue; the bound ref in useFilters.js updates. Because the refs are module-level, every component using useFilters() sees the new value.
  2. The active view (e.g. Dashboard.vue) watches the filter state and calls getCurrentFilters(), which maps UI fields to API params (selectedLocation → warehouse, selectedPeriod → month).
  3. The view calls api.getDashboardSummary(filters) in api.js, which drops any 'all' values and builds a query string via URLSearchParams.
  4. axios issues GET /api/dashboard/summary?warehouse=Tokyo&month=Q3-2025 to FastAPI.
  5. The handler runs apply_filters() (warehouse / category / status) then filter_by_month() (direct month like 2025-07 or a quarter via QUARTER_MAP) against inventory_items and orders.
  6. It computes aggregates — total inventory value, low-stock count, pending orders, backlog count, total order value — and returns a plain dict as JSON.
  7. The view stores the response in refs; computed properties derive display values and Vue re-renders the metric cards and SVG charts.

Key Patterns

Reactivity

Raw API data in refs; all derived values in computed. Module-level refs in composables act as a lightweight global store.

Filtering

Sequential, case-insensitive, skip on 'all'. Filters build new lists — original datasets are never mutated. Inventory has no time dimension, so it ignores month.

Validation

Pydantic response_model on list endpoints enforces output shape. Update the models whenever the JSON structure changes.

Statelessness

No sessions, no writes to disk. Any "mutation" lives only in the running process; a restart reloads from JSON.

Notes & Observations

Frontend/backend drift on this branch (new_features). client/src/api.js defines calls to /api/tasks (GET/POST/DELETE/PATCH) and /api/purchase-orders (GET/POST), and App.vue uses the tasks calls — but server/main.py does not implement those routes. The UI catches the resulting errors and logs them, falling back to mock task data from useAuth. purchase_orders.json is an empty array, so has_purchase_order is always false. These look like in-progress features.
Demo-only posture. CORS is fully open, there is no authentication or rate limiting, and input validation is limited to Pydantic types. The server/CLAUDE.md and root README.md both call this out as not production-ready without a database, auth, and security hardening.
